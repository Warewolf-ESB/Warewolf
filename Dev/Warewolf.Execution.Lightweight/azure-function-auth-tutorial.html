STEP 01

Easy Auth + Entra ID Setup

Configure Azure App Service Authentication (Easy Auth) to protect your Function App using Microsoft Entra ID (formerly Azure AD) as the identity provider.

1.1 — Register App in Entra ID
1
Navigate to Microsoft Entra ID → App Registrations
▲

Go to portal.azure.com → Microsoft Entra ID → App Registrations → New Registration.

Portal Fields
# Fill in these fields: Name: wwengine-auth Supported account: Single tenant Redirect URI: Web → https://wwengine.azurewebsites.net/.auth/login/aad/callback
ℹ️ Save the Application (client) ID and Directory (tenant) ID — you'll need them in the next steps.
2
Create a Client Secret
▼

Under your app registration → Certificates & secrets → New client secret.

Settings
Description: wwengine-secret Expires: 24 months # or as per your policy
⚠️ Copy the secret Value immediately — it's only shown once. Store it in Azure Key Vault.
3
Expose an API — Add Application ID URI
▼

Go to Expose an API → Set Application ID URI → Add a Scope for your app.

Scope Configuration
Application ID URI: api://<your-client-id> Scope name: user_impersonation Who can consent: Admins and users Admin display: Access wwengine
1.2 — Enable Easy Auth on Function App
4
Enable Authentication in Azure Portal
▼

Navigate to your Function App → Authentication (in the left menu) → Add identity provider.

Easy Auth Configuration
Identity Provider: Microsoft App registration type: Pick an existing app App (client) ID: <your-client-id> Client secret: <your-client-secret> Issuer URL: https://login.microsoftonline.com/<tenant-id>/v2.0 # Unauthenticated requests Action: Return HTTP 401 (recommended for APIs) Token store: ON
5
Configure authsettingsV2 — Allow Public Routes
▼

Easy Auth applies globally by default. We need to bypass it for /public/* routes. Deploy an authsettings.json in your function app's wwwroot, or use the REST API to configure exclusions.

authsettingsV2.json
{ "platform": { "enabled": true }, "globalValidation": { "requireAuthentication": false, "unauthenticatedClientAction": "AllowAnonymous" }, "identityProviders": { "azureActiveDirectory": { "enabled": true, "registration": { "openIdIssuer": "https://login.microsoftonline.com/<TENANT_ID>/v2.0", "clientId": "<CLIENT_ID>", "clientSecretSettingName": "MICROSOFT_PROVIDER_AUTHENTICATION_SECRET" }, "validation": { "allowedAudiences": ["api://<CLIENT_ID>"] } } }, "login": { "routes": { "logoutEndpoint": "/.auth/logout" }, "tokenStore": { "enabled": true } } }
✅ With AllowAnonymous, Easy Auth validates tokens when present but doesn't block unauthenticated requests. Your C# code handles enforcement per route (see Step 4).
6
Verify Easy Auth is Working
▼

Test that the login flow works by visiting the Easy Auth login endpoint in your browser.

Test URLs
# Login endpoint — redirects to Microsoft login https://wwengine.azurewebsites.net/.auth/login/aad # Check authenticated user info (after login) https://wwengine.azurewebsites.net/.auth/me # Logout https://wwengine.azurewebsites.net/.auth/logout
STEP 02

Roles & Permissions

Define App Roles in Entra ID and enforce them in your Azure Function. Each /secure endpoint can require a specific role in the JWT token.

2.1 — Define App Roles in Entra

App Roles are defined in your App Registration's manifest and are included as roles claims in the JWT access token.

Role Name Value (claim) Access Level Allowed On
Admin wwengine.admin ADMIN /public + /secure
WorkflowUser wwengine.user USER /public + /secure
Viewer wwengine.viewer VIEWER /public only
(none) — ANON /public only
1
Add App Roles to Manifest
▲

Go to App Registration → Manifest and add the appRoles array:

manifest.json (appRoles section)
"appRoles": [ { "allowedMemberTypes": ["User", "Application"], "description": "Full admin access to workflow engine", "displayName": "Admin", "id": "11111111-1111-1111-1111-111111111111", "isEnabled": true, "value": "wwengine.admin" }, { "allowedMemberTypes": ["User"], "description": "Can execute and manage workflows", "displayName": "WorkflowUser", "id": "22222222-2222-2222-2222-222222222222", "isEnabled": true, "value": "wwengine.user" }, { "allowedMemberTypes": ["User"], "description": "Read-only access to public endpoints", "displayName": "Viewer", "id": "33333333-3333-3333-3333-333333333333", "isEnabled": true, "value": "wwengine.viewer" } ]
⚠️ Generate real GUIDs for the id fields. Use PowerShell: [System.Guid]::NewGuid().ToString()
2
Assign Users to Roles
▼

Go to Entra ID → Enterprise Applications → wwengine-auth → Users and groups → Add user/group.

Assignment Steps
1. Select: Users and groups → john@company.com 2. Select a role → WorkflowUser 3. Click Assign # Repeat for other users and roles as needed # Or assign a whole security group to a role
3
Enable "Assignment Required" (Optional but Recommended)
▼

Under Enterprise Applications → Properties, set Assignment required to Yes. This blocks users not assigned to any role from authenticating at all.

✅ With this enabled, only explicitly assigned users can get a token for your app — adding a layer of defence before your code even runs.
2.2 — How Roles Appear in JWT

When a user authenticates, their access token contains a roles claim. Easy Auth parses this and injects it as HTTP headers into your function.

Decoded JWT Payload
{ "aud": "api://<client-id>", "iss": "https://login.microsoftonline.com/<tenant-id>/v2.0", "oid": "user-object-id", "name": "John Smith", "preferred_username": "john@company.com", "roles": [ "wwengine.user" // ← roles assigned in Entra ], "scp": "user_impersonation" }
Easy Auth Injected Headers (available in C#)
X-MS-CLIENT-PRINCIPAL-NAME: john@company.com X-MS-CLIENT-PRINCIPAL-ID: <user-object-id> X-MS-CLIENT-PRINCIPAL-IDP: aad X-MS-CLIENT-PRINCIPAL: <base64 encoded claims JSON> X-MS-TOKEN-AAD-ACCESS-TOKEN: <raw JWT token>

4.3 — EasyAuth Middleware
C# — Middleware/AuthMiddleware.cs
using System.Text; using System.Text.Json; using Microsoft.Azure.Functions.Worker; using Microsoft.Azure.Functions.Worker.Middleware; /// <summary> /// Parses Easy Auth headers injected by Azure App Service /// and attaches the parsed user context to the function context. /// </summary> public class EasyAuthMiddleware : IFunctionsWorkerMiddleware { public async Task Invoke(FunctionContext context, FunctionExecutionDelegate next) { var httpContext = context.GetHttpContext(); if (httpContext != null) { var principal = ParseEasyAuthPrincipal(httpContext); if (principal != null) { // Store parsed user in Items for downstream access httpContext.Items["EasyAuthUser"] = principal; } } await next(context); } private static EasyAuthUser? ParseEasyAuthPrincipal(HttpContext httpContext) { try { // Easy Auth injects X-MS-CLIENT-PRINCIPAL as base64 JSON var header = httpContext.Request.Headers["X-MS-CLIENT-PRINCIPAL"] .FirstOrDefault(); if (string.IsNullOrEmpty(header)) return null; var decoded = Encoding.UTF8.GetString(Convert.FromBase64String(header)); var principal = JsonSerializer.Deserialize<EasyAuthPrincipal>(decoded); if (principal == null) return null; // Extract roles from the claims array var roles = principal.Claims ?.Where(c => c.Type == "roles") ?.Select(c => c.Value) ?.ToArray() ?? Array.Empty<string>(); var name = principal.Claims ?.FirstOrDefault(c => c.Type == "preferred_username" || c.Type == "name") ?.Value ?? "unknown"; return new EasyAuthUser { Name = name, Roles = roles }; } catch { return null; // Malformed header — treat as unauthenticated } } } // ── Models ─────────────────────────────────────────── public record EasyAuthUser { public required string Name { get; init; } public required string[] Roles { get; init; } public bool IsAuthenticated() => !string.IsNullOrEmpty(Name) && Name != "unknown"; public bool HasRole(string role) => Roles.Contains(role, StringComparer.OrdinalIgnoreCase); public bool HasAnyRole(params string[] roles) => roles.Any(HasRole); } public class EasyAuthPrincipal { [JsonPropertyName("claims")] public List<EasyAuthClaim>? Claims { get; set; } } public class EasyAuthClaim { [JsonPropertyName("typ")] public string Type { get; set; } = ""; [JsonPropertyName("val")] public string Value { get; set; } = ""; }
4.4 — Public Endpoint
C# — Functions/PublicOrdersFunction.cs
using Microsoft.Azure.Functions.Worker; using Microsoft.Azure.Functions.Worker.Http; using Microsoft.Extensions.Logging; public class PublicOrdersFunction(ILogger<PublicOrdersFunction> logger) { /// GET /public/orders.json?id={id} /// No authentication required — open to all. [Function("PublicOrders")] public async Task<HttpResponseData> Run( [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "public/orders.json")] HttpRequestData req) { var id = req.Url.Query.TrimStart('?') .Split('&') .FirstOrDefault(x => x.StartsWith("id=")) ?.Split('=')[1] ?? "0"; logger.LogInformation("Public orders request for id={Id}", id); // Optional: log if caller is authenticated (but don't require it) var user = req.FunctionContext.GetHttpContext() ?.Items["EasyAuthUser"] as EasyAuthUser; if (user?.IsAuthenticated() == true) logger.LogInformation("Caller: {User}", user.Name); var order = new { id, status = "public", description = "Publicly accessible order summary", timestamp = DateTimeOffset.UtcNow }; var response = req.CreateResponse(System.Net.HttpStatusCode.OK); response.Headers.Add("Content-Type", "application/json"); await response.WriteAsJsonAsync(order); return response; } }
4.5 — Secure Endpoint
C# — Functions/SecureOrdersFunction.cs
using Microsoft.Azure.Functions.Worker; using Microsoft.Azure.Functions.Worker.Http; using Microsoft.Extensions.Logging; using System.Net; public class SecureOrdersFunction(ILogger<SecureOrdersFunction> logger) { /// GET /secure/orders.json?id={id} /// Requires authentication + role: wwengine.user OR wwengine.admin [Function("SecureOrders")] public async Task<HttpResponseData> Run( [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "secure/orders.json")] HttpRequestData req) { var httpContext = req.FunctionContext.GetHttpContext(); var user = httpContext?.Items["EasyAuthUser"] as EasyAuthUser; // ── Auth Check 1: Must be authenticated ────────── if (user == null || !user.IsAuthenticated()) { logger.LogWarning("Unauthenticated request to /secure/orders.json"); return Unauthorized(req, "Authentication required"); } // ── Auth Check 2: Must have required role ───────── var allowedRoles = new[] { "wwengine.user", "wwengine.admin" }; if (!user.HasAnyRole(allowedRoles)) { logger.LogWarning("Forbidden: {User} roles={Roles}", user.Name, string.Join(",", user.Roles)); return Forbidden(req, "Insufficient role. Required: wwengine.user or wwengine.admin"); } // ── Business Logic ──────────────────────────────── var id = req.Url.Query.TrimStart('?') .Split('&') .FirstOrDefault(x => x.StartsWith("id=")) ?.Split('=')[1] ?? "0"; logger.LogInformation("Secure order {Id} requested by {User} [{Roles}]", id, user.Name, string.Join(",", user.Roles)); // Admins see extra fields object order = user.HasRole("wwengine.admin") ? new { id, status = "secure", description = "Full order detail (admin view)", internalCost = 99.99, auditLog = "visible to admins only", requestedBy = user.Name, timestamp = DateTimeOffset.UtcNow } : new { id, status = "secure", description = "Order detail (user view)", requestedBy = user.Name, timestamp = DateTimeOffset.UtcNow }; var response = req.CreateResponse(HttpStatusCode.OK); response.Headers.Add("Content-Type", "application/json"); await response.WriteAsJsonAsync(order); return response; } // ── Helpers ─────────────────────────────────────── private static HttpResponseData Unauthorized(HttpRequestData req, string msg) { var r = req.CreateResponse(HttpStatusCode.Unauthorized); r.Headers.Add("WWW-Authenticate", "Bearer"); r.WriteString(System.Text.Json.JsonSerializer.Serialize(new { error = msg })); return r; } private static HttpResponseData Forbidden(HttpRequestData req, string msg) { var r = req.CreateResponse(HttpStatusCode.Forbidden); r.WriteString(System.Text.Json.JsonSerializer.Serialize(new { error = msg })); return r; } }
