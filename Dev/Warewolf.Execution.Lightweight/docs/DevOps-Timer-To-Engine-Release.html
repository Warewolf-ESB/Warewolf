Part 2 — Change the timer app settings Azure portal › Function App › Settings › Environment variables Infrastructure team

1Open the timer Function App tuprofilerdev2-function › Settings › Identity. System assigned must be On. Note the Object (principal) ID.
→
2Environment variables › App settings › Add the two settings below. Write down the old values first.
→
3Apply, then Confirm. The app restarts.
SettingValue
GenericBaseURLhttps://wwprofilerlw.azurewebsites.net/  (keep the trailing slash)
GenericEngineResourceAppIdfd3359c7-13e1-4a6e-8ab2-2fe6c56df1f7  (Application (client) ID of the engine's Entra app wwprofilerlw-auth)
Setting GenericEngineResourceAppId switches the app from the VM server to the engine: it drops the Profiler/ URL prefix and calls with its managed-identity token instead of GenericSecureWarewolfAuthorizationToken. Leave the old token setting in place for rollback. To roll back, restore the old GenericBaseURL and delete GenericEngineResourceAppId.

Part 3 — Give the timer's managed identity the Warewolf_ClientApps role Microsoft Entra admin center Infrastructure team · Application Administrator or Cloud Application Administrator

A. Create the app role (skip if it already exists)

1Entra admin center › App registrations › All applications › wwprofilerlw-auth
2App roles › Create app role
Display nameWarewolf ClientApps
Allowed member typesApplications
ValueWarewolf_ClientApps
DescriptionApp-only callers of Warewolf workflows
EnabledTicked › Apply

B. Assign it to the timer's managed identity

3The portal's Users and groups blade cannot pick a managed identity. Open Cloud Shell (Azure portal top bar, >_, Bash) and run: 
az ad sp show --id fd3359c7-13e1-4a6e-8ab2-2fe6c56df1f7 \
  --query "{sp:id, roleId:appRoles[?value=='Warewolf_ClientApps']|[0].id}"

az rest --method POST \
  --url https://graph.microsoft.com/v1.0/servicePrincipals/<sp>/appRoleAssignedTo \
  --body '{"principalId":"<timer principal ID from Part 2>",
           "resourceId":"<sp>","appRoleId":"<roleId>"}'
<sp> and <roleId> come from the first command's output.
4Check: Entra › Enterprise applications › wwprofilerlw-auth › Users and groups lists tuprofilerdev2-function with role Warewolf_ClientApps.
The engine must also grant the Warewolf_ClientApps group View + Execute on secure/Profiler/V2/Functions/ProfilerAlerts/GrantDates.json (its authorization config / secure.config). Without it the engine returns an authorization error even with the role assigned.
